PRODUCT AND RESEARCH PURPOSE

A researcher brings ordinary custom PyTorch code, a model/checkpoint, a question and a budget. Eidos's internal LLM investigates failures, runs experiments, authors or installs reusable components, and proposes changes to data, weights, learning rules or architecture. It produces a loadable model when justified, a reproducible recipe, and scoped conclusions backed by evidence. Humans and external agents operate the same lab through CLI and MCP.

The research question is whether Eidos helps the same underlying LLM obtain more independently verified improvements on unfamiliar model-research tasks under comparable budgets. Better performance is a hypothesis to test. Building the software or passing its acceptance tests does not establish scientific superiority.

5. Study charters fix scientific success rules before exploration. Plans inherit them. Later changes retain exposure history. Template/assessor approval requires executed planted-effect detection and null-case controls, not a human signature alone.

7. Checkpoint branches have immutable parents, private mutable child state, explicit state mappings, restore classes, behavioral checks and inherited/additional cost accounting. Replacing a component affects future bindings; changed running scientific behavior creates a branch. Preserve past evidence and explicit withdrawal/reassessment semantics.
8. Version context policies and retain turn specifications, source horizons, context snapshots, decisions and receipts for recovery and isolated offline evaluation without future-information leakage.
9.
