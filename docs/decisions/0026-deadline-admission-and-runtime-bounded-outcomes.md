# ADR 0026: Deadline admission and runtime bounded outcomes

Status: accepted (prospective; amended after R18; no pilot records changed)

D3 found six valid N01-r2 read responses stranded with 221–249 seconds left because follow-up admission required the full configured 300-second request timeout. The runtime fabricated empty waits, correctly refused by the no-outstanding-work validator. Runtime inability was misclassified as model proposal behavior.

Every provider request, including native tool follow-ups, now uses the smaller of its configured timeout and the actual decision/turn time left minus a two-second durable-write margin. The activity retains its existing watchdog margin, cancellation watcher, token reservation, per-decision request cap and Temporal turn boundary. HTTP timeout and a total request timer both enforce this budget. Context reports remaining time and the usable request budget. A late slot uses the current turn boundary rather than restarting the original allowance.

Insufficient time or abandonment at that boundary returns `DecisionResult.runtime_outcome = deadline-exhausted`, with no proposal. Usage, uncertainty and admitted in-flight estimates are settled as before. A separate `runtime_outcome` record and `decision.runtime_bounded` event retain the raw response reference. Runtime bounds never become invalid model decisions or exempt empty waits from validation. Other malformed proposal refusals remain model-origin errors.

At the true exploration boundary, the coordinator immediately commits the ordinary finalization phase while reproduction/export/confirmation time remains. That durable phase retains the existing effect permissions and the separate conclusion reserve. A deadline at that later reserve starts the existing fresh conclusion turn; only a turn carrying `exploration_deadline_unix` uses exploration-boundary admission. Only a runtime outcome leaving no usable decision, repeated refused proposals, or arrival after the ordinary finalization time has gone can admit the single conclude-only recovery of ADR 0027. Operator policy may enter ordinary finalization; a disabled recovery admission explicitly waits for operator input without repeated deadline turns. Child failure/timeout reconciliation closes an active recovery and writes its structured receipt before any ordinary retry. All time and tokens remain inside the original envelope.

The study arm pins the lab's optional absolute deadline to its outer watchdog minus a five-second export margin. Registration clamps that timestamp against the existing relative wall duration, so setup or command transport latency cannot extend the wall envelope. The ledger checks the effective deadline under the investigation lock after preparing the claim state and before writing the investigator conclusion. A late completion records a deadline failure and the default controller abstention. Prior operator stop or pause takes precedence. Offline tests cover delayed registration, a slow provider and a queued completion held past the deadline. A database or workflow outage can prevent an on-time durable write, and a late activity cannot manufacture success.

Validation: the N01-r2 fixture contains exact assistant text extracted from six SHA-256-verified historical response blobs, the matching original usage receipts, transcript line citations and per-turn 249/233/221-second limits. The coordinator replay preserves turns 10–12 and slots 0–1 in order; every historical read response gets its formerly blocked follow-up, with usage and elapsed time checked. Follow-up decisions are explicitly synthetic because the historical runtime never admitted them. Margin exhaustion yields no wait; cancellation and uncertain usage retain their existing tests. This changes prospective system behavior and supplies no evidence of counterfactual pilot success.


The Tier-0 coordinator consumer also covers the four archived crash tails from N01-r1, N01-r2, N03-r1 and N04-r2. It verifies the original provider request identifiers, token totals and read arguments, scales the timing envelope, and preserves the accepted N04-r2 slot and effect receipt. The recorded pilot never issued the newly admitted follow-ups or reached a recovery turn. The test marks the synthetic divergence and records a controller abstention without inventing a pilot conclusion. A separate terminal quota replay uses N02-r2's actual zero-reply provider failure receipt.
