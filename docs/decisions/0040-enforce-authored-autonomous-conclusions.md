# ADR 0040 — Enforce authored autonomous conclusions before effects

Status: Accepted for the prospective runtime and study adapter.

The independent review reproduced autonomous finalization replies that passed early runtime parsing but failed durable acceptance after their only logical decision slot. It also found supplied scope values that could be treated as omitted and an export fallback that did not identify its author.

A parsed autonomous proposal must have no effect calls and must conclude or stop, including before the read cap. The native output schema and supported JSON response schema advertise this restriction from the first request. Text-only endpoints rely on runtime validation. A positive disposition without the pinned eligible lock is refused. Contract errors may receive the existing single decision-only correction within the original request, token and wall ceilings. Both native-tool and text modes stop offering reads during this correction. A runaway that forces a decision-only continuation records that the model must work from the evidence already available. The lab remains authoritative and applies its own checks before effects. The runtime retains actual replies and structured refusal information without authoring a replacement conclusion.

With an operator contract, the validator checks a supplied scope as authored, including a non-object or null. Omitted scope and legacy investigations without a contract retain their previous behavior. The study contract also requires a genuine abstention to include nonblank reason and next test and a nonempty list of obligations. A terminal scope-contract refusal can be attributed from its durable record and classified as invalid output; provider and wall precedence are preserved. If the adapter generates abstention metadata because authorship is absent or the authored boolean conflicts with the exported status, the export identifies adapter authorship and a private receipt preserves the authored value. Malformed matching metadata is not silently replaced.

The prospective synthetic tests exercise the correction, no-effect refusal, malformed actual values and provider bounds. The study contract is partial shape validation. It does not establish the quality of a conclusion or any scientific verification.


The text path preserves the advertised claim object and accepts the existing encoded claim form when supplied alone. A reply that supplies both forms is refused. Both runtime modes use the durable claim-block validator before offering the same bounded correction. In native mode a runaway followed by an unusable authored reply stays a typed runtime outcome; a provider failure keeps its existing taxonomy. A decision-only repair records when it forfeits an available read round, independently of whether the final conclusion is valid. The Arm 4 run record distinguishes forfeiture, no available read rounds, no observed forfeiture and unavailable evidence.

The durable finalization record binds an authored refusal to its typed runtime record and a bounded list of actual problems. Scope-contract, claim-contract, disallowed-control, positive-without-lock and authored output-shape terminal refusals map to `invalid_output` in Arm 4. Wall and budget exhaustion and provider incidents retain priority. Empty output, runaway without an authored terminal refusal and unknown failure retain their existing non-authored outcome. A valid investigator conclusion after correction stays `ok`; valid authored abstention with no eligible lock can carry a descriptive cause without changing its status. Controller fallback remains distinct.

The model-facing revision is `investigator-prompt/4` because the tool guide, claim shape and finalization response guidance changed. The context packing algorithm and cap remain pinned separately. Accepted decisions record the prompt revision and the turn context retains its own source identity.

For Arms 1–3, an explicit final error sets the terminal classification from its own fields. Provider errors yield incidents and other or unknown final errors yield crashes. If the result is missing, the latest unresolved provider error can still yield an incident. A later distinct completed assistant response with usage resolves that error. Retry notices, tool outputs, partial responses and repeated assistant messages leave it unresolved. Final success and enforced wall and token outcomes retain their existing precedence. Raw stderr remains in the transcript. A failure supported only by stderr text has unknown provider origin and is classified as a crash.

The Claude CLI has a legacy rate-limit envelope whose final result has subtype `success` and `is_error: true`. A final envelope without explicit error or status fields can corroborate an unresolved typed synthetic assistant `rate_limit` only if its entire result exactly echoes that event’s single `API Error:` text block. A later provider error replaces the possible echo, and a distinct completed response resolves it.

The study launcher retains a recorded crash, timeout, token-budget outcome or invalid output when no served model ID is available. A successful run still requires the registered model ID. An observed different model, a missing run record or a reported incident retains the existing block incident handling.
