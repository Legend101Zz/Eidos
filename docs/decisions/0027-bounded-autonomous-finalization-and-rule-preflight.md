# ADR 0027: Bounded autonomous finalization and rule preflight

Status: accepted (prospective; amended after R18)

An investigation fixes `investigator.finalization` at start: `autonomous` (default) or `operator`. Two durable states have different purposes:

- Ordinary `finalize` is the existing exploration phase, reached at a perfect score, patience/search limit, selection freeze, or wall/token hold-back. `investigation_finalization_phase` records its trigger and `mode: ordinary`; subsequent turns retain it. Reproduction, export, evidence-plan/assessment admission and independent confirmation retain their existing permissions and validators. Selection cannot restart. Ordinary turns preserve the conclusion reserve.
- Bounded recovery uses `investigation_finalization` with `mode: conclude-only`. Autonomous policy admits it after repeated refused-proposal turns, a runtime deadline outcome with no usable decision, or reaching the boundary after the time for ordinary finalization has gone (the conclusion reserve has begun). A healthy ordinary `finalize` phase alone never admits this route. There is at most one recovery turn, with one decision slot; read round trips still count against the configured per-decision request maximum. Operator policy disables this recovery. At a real exploration boundary it can still enter the permitted ordinary phase; a disabled admission is explicitly surfaced as an operator wait, without repeated deadline turns.

The recovery snapshot supplies exact persisted refusal reasons and response references, runtime outcome, the locked incumbent and its source/job/output receipt identifiers, existing visible metrics and their inputs/configuration, recognized reproduction status, the fixed rule, remaining wall time and budgets. It requires reporting the locked candidate with provenance limitations, or honest abstention when none is eligible. The immutable snapshot is supplied even if context windowing would omit older evidence.

Both kinds of finalization record a per-turn evidence allowlist. Ordinary finalization also admits its newly recorded, provenance-safe reproduction evidence within the same turn, and retains structural confirmation handles/obligations without result payloads; recovery's evidence snapshot stays fixed. Charter-held-out label digests, restricted artifacts and evidence-arm/plan jobs are excluded. Exclusion follows job inputs, producer outputs, recorded lineage, attested split names and digest aliases to a fixed point over the entire project, so derived evidence and chains crossing investigation boundaries stay isolated. The evidence queries check membership and current provenance before any artifact bytes or job terminal information are exposed. Component descriptions and the packed catalog are also gated. A finalization context query projects only admitted jobs/artifacts and removes unqualified free-form result histories and held-out references before packing any context policy or storing its source manifest. During exploration, project evidence reads also exclude attested held-out provenance and internal model traces. Model prompts, read results and same-turn feedback exclude held-out identifiers and digests. The internal source manifest retains the charter attestation separately for audit. Project artifact access alone does not authorize held-out disclosure. Independent assessor conclusions remain derived from the ledger; absence of held-out evidence never becomes a passed assessment.

Conclude-only recovery offers evidence reads (`get_job`, `inspect_evidence`, `describe_component`) and `conclude`/`stop` only. Catalog search is removed, the effect-call allowance is zero, and the command service independently validates the action. No training, authoring, rule changes, candidate changes, new search or model-selected re-lock is possible through recovery. These restrictions do not apply to ordinary finalization's permitted scientific work.

Recovery uses the original wall deadline including the remaining hold-back. Every request fits the time left. Its reservation shrinks to the remaining original token/USD budget. Usage is charged through the existing ledger with `phase: finalization`, including failed/cancelled calls; separate accounting never adds allowance. Failure ends the default run with a structured `controller-abstention/1` record, attributed to the controller, and a durable `finalization_export_receipt` preserving the incumbent, failure and limitations. Terminal limits and terminal provider failures after a lock use the same explicit abstention. The investigation remains eligible for an explicit operator resume without another bounded recovery. Operator-policy runs still expose operator input when needed. After a child workflow failure or execution timeout, the coordinator reconciles durable recovery state before ordinary retry handling. A new coordinator also reconciles an abandoned running recovery before beginning a child. The same atomic turn closure settles uncertain reservations and writes the structured failure and export receipt. Activity retries and restarts return the existing receipt; recovery is never reopened. Pending recovery with no failed child remains eligible for its one turn. If the child fails before `begin_turn` commits, reconciliation closes the pending admission with the child failure and export receipt; a late begin is fenced by its finished state. A controller abstention preserves `investigator_concluded: false` and the failed run outcome. Terminal provider failures retain the incident classification.

Before a selection rule is first recorded (including a first lock carrying one), its data input bindings must name ports in the scorer's published manifest. Unknown scorers or impossible bindings are refused before an immutable note is committed, naming actual ports. An unversioned scorer is checked against every active matching release; pin a release if contracts differ. Existing recorded rules remain immutable, including historical misbindings. Classification binds labels to `reference`, not the scientific split name `validation`. The guide illustrates fresh-seed reproduction without fixing the intentionally varied seed in the selection rule.

Every refused decision preserves its `response_artifact_id` for transcript export. Runtime outcomes retain their own event/record and response reference separately from model errors.

Validation includes healthy incumbent/challenger and confirmation flows under the default policy, real boundary admission under both policies, direct/derived/aliased held-out read and packed-context isolation, child failure/timeout and restart reconciliation, and the verified historical six-slot N01-r2 coordinator replay. No pilot records are modified. This policy provides a within-envelope reporting opportunity; it cannot guarantee provider availability, eligible evidence, reproduction or independent success. Comparisons must disclose it and preserve comparable final-answer opportunities for other arms.
